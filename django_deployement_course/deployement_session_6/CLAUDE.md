## This deck is assembled from parts, and that is deliberate

Sessions 1 to 5 are each one deck file. This one composes three, because it was
generated by three agents in parallel:

```
deckShared.tsx      constants, Code, Tech + TECH_SRC, every reused transcript
partFrontC1.tsx     slides 1 to 20
partC2C3.tsx        slides 21 to 38
partC4Closing.tsx   slides 39 to 53
dockerHubDeck.tsx   spreads the three in plan order, and carries R1 to R8
```

The split is by concept and the shared file holds everything two parts could
disagree about. **Anything that appears on more than one slide belongs in
`deckShared.tsx`**, not copied into two parts: that is the only thing keeping
four authors' work consistent.

## Running it

`vite.config.ts` hardcodes port 5173 and every harness reads `devPort` from
`deck.config.json`. They have never agreed, in any session, so start the server
explicitly:

```bash
npm install
npx vite --port 5217 --strictPort        # NOT `npm run dev`
```

Then, from another shell:

```bash
npm run typecheck
npm run build:html                       # -> dist-single/deployment-session-6.html

export CHROME_PATH=/opt/google/chrome/chrome
node video-safe.mjs                      # must print CLEAN
node qa.mjs                              # baseline is TWO slides: 1 and 53
node align-check.mjs                     # must print 0 of 53
node preview.mjs && node scripts/build-preview-page.mjs
```

## Three things that will bite an editor

**`CodeBlock`'s `language` prop defaults to `'python'`, and it is also the chip
label.** Every Makefile panel here passes `language="makefile"` and every shell
panel `language="bash"`. Omit it and the slide ships a `python` chip on a
Makefile, with no type error.

**Every indented line in `MK_SESSION_5` and `MK_WITH_PUSH` is a real tab.**
Session 5 taught that Make accepts exactly one indentation character.
Reformatting those strings with spaces makes this deck contradict the previous
one.

**Nothing in this deck is captured.** Docker Desktop cannot run on the capture
machine, and this session additionally needs a real Docker Hub account and a
real push, so every transcript is quoted from the TR. Slide 35, the Hub
repository page, is the slide this constrains most: it is text and a code block
on purpose, not a browser screenshot.

## The two figures are session-owned

`ImageNameAnatomy` and `TagPointers` sit in this session's `src/ui/` and are
exported from its barrel. `sync-kit.mjs` will not touch them, because it only
overwrites the files it lists. `ImageNameAnatomy` is the candidate for promotion
to the kit, since sessions 7 to 9 name images constantly, but that is the user's
call under content rule 14 and it has not been made.

Both are built from real DOM elements rather than SVG text, for the reason
session 5 recorded for `TargetAnatomy`: SVG text does not wrap, does not inherit
the type scale, and cannot be highlighted one part at a time.
