Working with Dictionaries

Session 30 · 75 minutes · 27 cards · 24 beats · handout Task 1, Task 2

The one idea

b = a gives one dictionary a second name, so a change through either name is seen by both; copy() makes a second dictionary. A function with *args or **kwargs takes any number of arguments: values with no name pack into a tuple, name=value arguments pack into a dictionary.

By the end, a student can

  • Say what b = a does to a dictionary, and show it with id().
  • Make a separate dictionary with copy(), and say which name sees a change.
  • Empty a dictionary with clear(), count it with len(), check a key with in.
  • Explain why deleting keys inside a loop over the same dictionary stops with RuntimeError, and loop over a copy instead.
  • Write a function with *args, say it packs a tuple, and open a list with * at the call.
  • Write a function with **kwargs, say it packs a dictionary, and open a dictionary with ** at the call.
  • Say where each argument of a call lands, and when Python stops with TypeError.

  2. Commit, then reveal. Where a card asks a question, the answer shows only on the press after the room has answered.
  3. Wrong answers stay private. No names, no per-student results on screen. Hands are counted out loud, never shown.
  4. The topic is named once. Nothing before the title card says today's topic, not a heading, not a caption, not a file name on a code card.
  5. Words are exact. Words in quotation marks, and every line under Exact words, are final. The rest of a press describes what happens, in your own design. If an exact line does not fit, ask for a new one; do not rewrite it.
  6. Code is exact. Copy code and outputs from the JSON, never retype them. Every output here came from running the program.
  7. Simple English. Short sentences, everyday words. No em-dashes anywhere, the page title included.
  8. Every card moves. A card that introduces an idea steps; a static card is a picture of a lecture.

The game: Where does it land?

A function's parameters are drawn as boxes: one box per named parameter, a tuple box for *args, a dictionary box for **kwargs. The room votes on what the print line shows; then each argument of the call flies to its box, one per press, or Python stops with TypeError before the body runs.

  1. The program on one side: the def line, its body and the call. On the other, the parameter boxes in the def's order: a plain box for each named parameter, a tuple box for *name, a dictionary box for **name. The boxes start empty: the tuple box shows (), the dictionary box {}.
  2. The room votes on what the print line shows. Options are concrete values, or TypeError; the full error line shows on the verdict.
  3. One press per argument, left to right as the call is written. A value with no name= goes to the next empty named box; when those are full it joins the tuple box. A name=value goes to the box with that name; if no box has that name it joins the dictionary box as a key-value pair.
  4. *list and **dict at the call open first, on their own press: the list becomes separate values, the dictionary becomes name=value arguments. Then they land like any other argument.
  5. If an argument has nowhere to go, or a named box is still empty at the end, Python stops with TypeError. The body never runs and nothing prints.
  6. If every argument lands, the body runs on one more press and the terminal fills.
